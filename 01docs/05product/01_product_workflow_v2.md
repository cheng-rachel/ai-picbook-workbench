# Power Up Picture Book Forge — Product Workflow

> 文件路径建议：`01docs/05product/01_product_workflow_v2.md`  
> 文档角色：定义 Power Up Picture Book Forge（Power Up 绘编）Demo 的端到端产品流程，是后续 Data Mapping、Data Dictionary、Validation Rules、Generation Rules、RAG Mapping 的上位流程依据。

---

## 1. 产品定位

Power Up 绘编不是“一键生成绘本”的自动写作工具，而是一个：

> **以 Cambridge Power Up 2 教材为依据、教师筛选为核心、AI辅助发散与编写、语言指标可检测的分级绘本教研工作台。**

产品采用 **Proposal-first + Human-in-the-loop** 工作流。

核心逻辑：

1. Proposal 决定故事骨架；
2. 教师筛选和确认后，系统再生成正文；
3. 正文生成后由程序进行语言检查；
4. AI负责建议、生成、改写和语义判断；
5. 教师拥有 Proposal、词汇身份、正文版本和 Final 的最终决定权；
6. 只有 Final 绘本才进入历史绘本库、动态词汇库和复现统计。

## 3. 绘本分类

产品统一使用以下三类术语：

1. **教材衔接**
2. **主题拓展**
3. **跨学科提升**

### 3.1 教材衔接

核心定位：

> 换情境，练所学。

要求：

- 紧密衔接教材单元的核心主题、语言功能及主要语言项目；
- 优先使用教材核心词汇和句型；
- 不直接复述或模仿教材原有故事情节，通过新的角色、问题或情境实现语言迁移；
- 主要承担课堂所学内容的巩固与迁移。

### 3.2 主题拓展

核心定位：

> 从主题出发，进一步思考。

要求：

- 保留教材的大主题，但可以离开教材原有活动和具体语言情境；
- 进一步拓展相关的生活经验、行为方式、情感态度和社会认知；
- 可以引入必要的主题拓展词；
- 不应只是更换人物、地点或道具的“换皮故事”。

### 3.3 跨学科提升

核心定位：

> 借主题认识更大的世界。

要求：

- 以教材主题作为入口，选择与单元主题自然相关、符合儿童认知水平的内容；
- 通过跨学科知识（自然科学、社会科学、人文、艺术等）的感知、理解和比较展开；
- 优先选择能够自然融入故事的跨学科切入点；
- 不为了体现“跨学科或跨文化”而进行生硬对比或强行偏离教材主题。

## 4. 最高优先级产品原则

### P1. 教材事实必须可追溯

教材 Unit Title、Theme、Essential Question、Textbook Words、Grammar、Cross-curricular、Literature 等事实不得由 LLM 猜测，应从结构化数据中精确读取。

### P2. 故事与语用自然性优先

不得为了：

- 塞入某个词；
- 达到某个词频；
- 达到句型重复次数；
- 机械复现教材表达；

而破坏故事逻辑或生成不自然英语。

### P3. Proposal 决定故事骨架

Proposal 必须包含完整的初步故事逻辑。

正文阶段可以调整：

- 情节比重；
- 循环方式；
- 对话与叙述比例；
- 语言出现位置；
- 节奏和结尾表达；

但不应无依据加入会改变核心因果链的重大事件。

### P4. 科学复现不是机械重复

核心语言应在：

- 不同绘本；
- 不同语境；
- 不同级别；

中自然复现。

复现服务于理解和使用，不服务于“凑次数”。

### P5. 教师拥有最终决定权

AI可以推荐、生成、改写、分类、预警。

AI不能自动：

- 选择最终 Proposal；
- 确认核心词身份；
- 确认拓展词身份；
- 忽略 Warning；
- 把 Draft 写入正式动态词库；
- 把绘本自动设为 Final。

### P6. 事实准确性高于语言简化

涉及：

- 自然；
- 健康；
- 文化；
- 历史；
- 生活常识；

等事实内容时，不得因为降低语言难度而牺牲事实准确性。

Demo 第一版不自动联网核验事实；涉及需核验内容时，必须由教师手动核验并填写备注，未完成则阻止 Final。

# 5. 系统总体工作流

```text
首页 / 项目工作台
        ↓
选择 Level / Unit
        ↓
读取教材结构化数据 + Level 规则
        ↓
教师调整生成输入
        ↓
生成 6–10 个 Proposal
        ↓
教师人工筛选 Proposal
        ↓
正文生成前确认
  ├─ 计划核心词
  ├─ 计划拓展词
  ├─ 核心句型
  ├─ AI 推荐复现词
  ├─ 页数
  ├─ 词数目标
  └─ 故事 / 语言生成倾向
        ↓
生成 2–3 个正文版本
        ↓
自动 Validation
        ↓
教师编辑 / 单页重写 / 全文重写 / 锁句
        ↓
每次修改后重新 Validation
        ↓
确认本版词表
        ↓
形成待定稿核心词 / 待定稿拓展词
        ↓
可选生成 Key Visual / 上传风格锚点
        ↓
Final Check
        ↓
教师二次确认 Final
        ↓
写入历史绘本库 + 动态词汇库 + 复现统计
        ↓
Word / Excel 导出
```

# 6. Stage 0 — 首页 / 项目工作台

## 6.1 页面目标

首页不是登录页，而是教师的项目工作台。

建议至少包含：

- Power Up 2 全部 Unit 列表
- 历史绘本库
- 导出中心
- 体系词汇进度

## 6.2 Topic 入口

教师选择：

- Level
- Unit

例如：

> Level 2 → Power Up 2 Unit 3 · Party time!

## 6.3 体系进度

首页可以显示轻量统计：

- 核心词：已沉淀 X / Level 2 本级新增目标约 504 词（03语言项目收录标准）
- 拓展词：已沉淀 Y（单篇参考约 4 个，Human Source 未设累计目标）
- 复现词：已沉淀 Z（无累计目标）

说明：

- “已沉淀”只统计 Final 绘本；
- Demo 按 lemma 去重统计；
- 首页明确标注：**“按 lemma 统计，暂未区分 multiword / 一词多义”**；
- 该区域仅用于体系建设总览；
- 不作为当前单篇绘本生成的硬约束。

## 6.4 项目保存

Demo 第一版：

- 不做正式账号体系；
- 项目默认本地自动保存；
- 教师可手动保存版本快照；
- 后续可扩展云端项目保存与多人协作。

# 7. Stage 1 — 读取教材依据

教师选择 Topic 后，系统从 Database 精确读取：

- Unit Title
- Theme
- Essential Question
- Textbook Words
- Textbook Structures（Grammar）
- Cross-curricular
- Literature
- 当前 Level 规则

其中：

- `Textbook Words` = 教材提供的词汇依据；
- `Textbook Structures` = 教材提供的语言结构依据；

不得直接等同于某一本绘本最终的“核心词”和“核心句”。

## 7.1 教材数据与 AI 内容必须区分

UI 应明确标识：

> 📘 教材依据

与：

> ✨ AI建议

避免教师误把 AI 推荐内容当作教材原文。

## 7.2 教师可修改生成输入

教师可以：

- 添加词汇；
- 删除词汇；
- 添加句型；
- 删除句型；
- 输入创作要求；
- 输入希望避开的内容。

教师修改形成当前项目的：

> `session overrides`

原始教材数据本身不被覆盖。

# 8. Stage 2 — Proposal 生成

## 8.1 Proposal 输入

Proposal Generator 使用：

### Database

- Topic 教材事实；
- Level 规则；
- 已有历史 Final 数据中需要精确查询的内容。

### RAG

按需检索：

- 设计理念；
- 分级原则；
- 主题拓展原则；
- 跨学科提升原则；
- 故事与语用原则；
- 语言项目解释性规则。

### Teacher Input

- session overrides；
- 创作偏好；
- 特殊要求。

### Prompt

负责把当前任务、结构化事实、RAG原则和教师要求组织成可执行生成指令。

---

# 9. Stage 2A — Proposal 多样性规划

在正式生成 Proposal 前，系统应先进行一次隐藏的：

> **Creative Diversification Planning**

该规划不直接展示给教师。

目标：

> 防止 6–10 个 Proposal 只是人物、地点、道具不同，但故事逻辑基本相同。

规划维度可以包括：

- 场景；
- 核心冲突；
- 情节驱动力；
- 问题解决机制；
- 结尾机制；
- 文体；
- 认知切入角度。

可以参考但不限于：

- 校园；
- 家庭；
- 自然；
- 游戏 / 挑战；
- 社会生活；
- 科学发现；
- 奇幻想象；
- 文化情境。

这些类别不作为固定槽位。

---

# 10. Stage 2B — Proposal 输出

每次生成：

> **6–10 个 Proposal**

默认建议：

> 8 个

每个 Proposal 至少包含：

1. Proposal 标题
2. 中文切入点描述
3. 详细故事线
4. 预测核心词
5. 预测核心句
6. 预测拓展词
7. 绘本分类
   - 教材衔接
   - 主题拓展
   - 跨学科提升
8. 情节结构
9. 潜在问题
10. 创意亮点（可选）

## 10.1 Proposal 的故事线要求

Proposal 不是完整绘本文本。

但必须包含：

> 起因 → 核心问题 → 发展方式 → 主要循环 / 转折 → 结局

它应足够完整，使教师能够在正文生成前判断：

> “我是否愿意让这个故事继续写下去？”

## 10.2 Proposal 轻量语言检查

Proposal 阶段只做轻量检查。

例如对预测核心词：

```text
候选词
  ↓
本单元教材词汇
  ↓
Power Up 2 教材全册词汇
  ↓
来源状态
```

未命中时：

> ⚠️ 未在当前核心词来源中发现，请人工核对。

此 Warning：

- 不阻止 Proposal 展示；
- 不自动删除该词；
- 不阻止教师继续生成正文。

---

# 11. Stage 3 — 教师筛选 Proposal

Proposal 默认卡片展示，并支持切换为表格视图。

教师可以：

- 选择一个 Proposal；
- 同时选择多个 Proposal；
- 修改 Proposal；
- 导出 Proposal Excel；
- 放弃 Proposal；
- 重新生成。

只有教师主动选择的 Proposal 才能进入正文生成阶段。

确认：

> **一个 Project = 最终一本绘本。**

若教师一次选择多个 Proposal，系统自动将其拆分为多个独立绘本项目；每个项目独立拥有计划词、复现词、Draft、Validation 与 Final 状态。

系统不得自动挑选“最佳 Proposal”后直接写正文。

---

# 12. Stage 4 — 正文生成前确认

这是 Proposal 与 Full Text 之间的关键人工决策点。

系统展示：

- Proposal 标题；
- 切入点；
- 完整故事骨架；
- 绘本分类；
- 情节结构；
- 潜在问题；
- 预测核心词；
- 预测拓展词；
- 预测核心句。

教师在此阶段进行最后一次生成条件调整。

---

# 13. Stage 4A — 计划词汇

Proposal 中的：

> 预测核心词

进入此阶段后变为：

> **计划核心词**

Proposal 中的：

> 预测拓展词

进入此阶段后变为：

> **计划拓展词**

教师可以：

- 增加；
- 删除；
- 修改；
- 调整身份。

此时仍不进入正式动态词汇库。

---

# 14. Stage 4B — AI 推荐复现词

AI 推荐复现词发生在：

> **Proposal 已选定之后，正文生成之前。**

## 14.1 推荐来源

Level 2 的待复现核心词池来自：

> **本地存储中当前有效 Final 的 Level 2 核心词。**

一个词第一次作为 `CORE` Final 时不计为复现；之后在其他 Final 绘本中以 `REVIEW` 身份出现，才形成 recurrence event。

推荐优先考虑：

- 当前本级累计复现不足；
- 与当前故事自然兼容；
- 不增加不必要的新概念；
- 可以在新语境中自然出现。

## 14.2 推荐数量与冷启动

```text
复现池 = 0
→ 不要求计划复现词，不 Warning

复现池 = 1–4
→ 有几个推荐几个，不 Warning

复现池 >= 5
→ 建议推荐 5–6 个
```

教师必须人工确认。

教师可以：

- 接受；
- 删除；
- 替换；
- 手动加入。

确认后形成：

> **计划复现词**

## 14.3 UI 信息

例如：

```text
red
本级累计复现：1/3
```

```text
friend
本级累计复现：2/3
```

## 14.4 Level 2 复现统计定义

“必会词复现 3–5 次”在本产品中定义为：

> **同一 Level 内，某词在不同 Final 绘本中的累计建议次数。**

3–5 次是建议目标，不是 Final 硬约束；不达标显示 Warning，由教师确认。

不是：

> 同一本绘本内部出现 3–5 次。

例如：

```text
red
Book A → 复现事件 1
Book B → 复现事件 2
Book C → 复现事件 3
```

若 `red` 在 Book C 中出现 6 次，对跨书复现统计仍只计：

> 1 个 book-level recurrence event

同一本正文内部的 token frequency 单独统计。

---

# 15. Stage 4C — 正文生成参数

教师确认：

## 15.1 页数

仅允许：

- 8 页
- 12 页

## 15.2 Level 2 总词数

当前 Demo 正式采用：

> **120–200 words**

建议生成中心目标：

> 约 150 words

## 15.3 每页句数

目标：

> 2–3 句 / 页

## 15.4 单句长度

目标：

> 原则上不超过 10 词

## 15.5 核心句型

目标：

> 1–2 个核心句型

## 15.6 核心句型内部重复

目标：

> 每个核心句型在单本内自然重复约 3–5 次。

这里与“跨书词汇复现”是两个完全不同的指标。

## 15.7 生成倾向

教师可选择：

- 故事优先
- 语言优先
- 平衡

系统在所选方向下生成多个版本。

如该机制效果不稳定，Demo 可降级为：

> 同一 Proposal 下直接生成 2–3 个有明显区别的正文版本。

---

# 16. Stage 5 — 正文生成

每个选中的 Proposal：

> 生成 2–3 个 Full Text 版本。

## 16.1 版本间允许变化

可以变化：

- 情节展开比重；
- 循环次数；
- 循环顺序；
- 对话 / 叙述比例；
- 语言出现位置；
- 转折强弱；
- 结尾呈现；
- 核心词与句型的自然承载方式。

## 16.2 不允许变化

不得：

- 无依据更换核心矛盾；
- 加入改变故事因果链的重要事件；
- 为满足词汇指标增加无关场景；
- 为套教材句型制造不自然英语；
- 为降低难度牺牲事实准确性。

---

# 17. Stage 6 — 自动 Validation

全文生成完成后自动进行完整检查。

Validation 由程序规则与必要的 AI 语义判断共同完成。

## 17.1 文本结构检查

程序检查：

- 总词数；
- 页数；
- 每页句数；
- 单句词数。

检查结果分为：

- Pass
- Warning

Demo 第一版原则上不因单一 Warning 自动阻止教师继续操作。

## 17.2 计划核心词检查

显示：

```text
lunch ×4  ✅
box   ×3  ✅
lost  ×1  ⚠️
```

核心词在单本中的目标出现次数可配置。

Demo 初始建议：

- 范围：1–5
- 默认：3

未达目标时显示 Warning，不自动强行改写。

## 17.3 计划拓展词检查

显示每个计划拓展词：

- 是否实际出现；
- 出现次数。

原则：

> 拓展词越少越好，以真实表达需求为依据。

不要求机械填满某个数量。

---

# 18. Stage 6A — 未分类内容词

系统扫描正文中的内容词。

若某词未被归入：

- 计划核心词；
- 计划拓展词；
- 计划复现词；

则进入：

> **未分类内容词**

系统：

1. 列出词项；
2. AI提供分类建议；
3. 教师最终确认。

建议身份可以包括：

- 核心词候选；
- 主题拓展词；
- 文化拓展词；
- 非教学性情境词；
- 普通已知词。

AI建议不能自动写入正式动态词库。

---

# 19. Stage 6B — 词汇来源检查

计划 / 待定稿核心词需要查询：

- 本单元教材词汇；
- Power Up 2 教材全册词汇（textbook scope）。

Demo 第一版采用：

> **lemma 归一化 + 人工复核 Warning**

支持基本情况：

```text
children → child
went → go
cars → car
```

暂不自动解决复杂情况：

- 一词多义；
- 完整派生关系；
- 词性转换后的语义一致性；
- 固定搭配的教学身份；
- 复杂合成词判断。

这些情况统一：

> 标记 Warning → 教师人工复核。

---

# 20. Stage 6C — 历史词汇冲突检查

系统查询：

> Final 绘本形成的动态词汇记录。

若当前计划 / 待定稿核心词已在历史 Final 绘本中作为：

- 核心词；
- 拓展词；

正式出现，则显示：

> 🔴 Historical Conflict Warning

必须告诉教师：

- 哪个 Level；
- 哪个 Unit；
- 哪个 Topic；
- 哪本绘本；
- 当时的词汇身份。

例如：

```text
find

已在：
Power Up 2 · Unit 2 · Book 03

历史身份：
核心词
```

操作：

- 查看历史记录；
- AI建议替换；
- 强制保留。

Historical Conflict 是 Warning，不是硬阻断。

Demo V1 只检查当前 Level 2：同 Level 中历史 `CORE / EXTENSION` 再作为当前 `CORE / EXTENSION` 时显示红色 Warning；历史仅作为 `REVIEW` 时不算冲突。跨 Level 暂不处理。

---

# 21. Stage 6D — 复现词检查

针对计划复现词，程序检查：

1. 当前正文是否出现；
2. 当前书内部出现次数；
3. 当前 Level 已累计多少个 book-level recurrence events；
4. 本书 Final 后累计值将如何变化。

例如：

```text
red

本书内部出现：4 次
当前 Level 累计：1/3
若本书 Final：2/3
```

若计划复现词完全未出现：

> ⚠️ Warning

教师可以：

- 修改正文；
- 删除该计划复现词；
- 更换复现词。

---

# 22. Stage 6E — 核心句型检查

核心句型按：

> **Pattern**

而不是逐字字符串一致进行统计。

例如：

```text
Where is my bag?
Where is my book?
Where is my coat?
```

应归为：

```text
Where is my ___? ×3
```

判断时优先考虑：

1. 语言知识点；
2. 语用功能；
3. 固定结构；
4. 可替换元素。

Demo 可以采用：

> 结构化 Pattern + 必要的 AI 辅助判断

而不是完全依赖自由文本 LLM 判断。

# 23. Stage 6F — 事实内容 Warning

若正文涉及：

- 自然科学；
- 健康；
- 文化；
- 历史；
- 生活常识；

则系统显示：

> ⚠️ 本绘本包含事实性内容，请完成人工核验并填写核验备注。

Demo 第一版不增加自动联网事实核验组件。

如果系统标记为需要事实核验，则教师必须：

1. 手动完成核验；
2. 填写核验备注；
3. 确认“已核验”。

未完成上述步骤：

> **Final Blocker：不能定稿。**

# 24. Stage 7 — 教师修改工作台

Demo 第一版必须支持：

## 24.2 单页重写

## 24.3 句子锁定

## 24.5 修改后重新校验

- 页数；
- 每页句数；
- 单句词数；
- 核心词；
- 拓展词；
- 未分类词；
- 复现词；
- 核心句型；
- 历史冲突。

# 30A. Unit Final 配额与完成状态

每个 Unit 必须最终形成 **7 本当前有效 Final**（03语言项目收录标准：Level 2 规划册数 63 册 ÷ 9 Units）：

```text
总计：恰好 7 本
三类在 7 本中的数量分配（2026-08-19 人工确认）：
教材衔接 2 / 主题拓展 3 / 跨学科提升 2
```

因此：

- 少于 7 本 → Unit 状态为 `INCOMPLETE`；
- 总数达到 7 → `COMPLETED`；
- 第 8、9……个 Proposal / Draft 可以长期保存为备选；
- Unit 总数已达 7 时，新的 Draft 仍可编辑，但 Final 时被 Blocker 阻止；
- 同类型 Final 已达该类型上限（2 / 3 / 2）时，同类型新 Final 同样被 Blocker 阻止。

# 37. Workflow 总原则

> **RAG 负责找到相关教研依据。**
